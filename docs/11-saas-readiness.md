Measure queue, required CI, packaging, promotion and first verified response individually before optimizing. ## Build sequence

1. **Make the first project observable.** Add production domain health and source readback to the owner console alongside the existing verified preview evidence. The first increment uses public GET requests to three fixed hosts and the existing sign-in gate. Keep production status explicit when hosts disagree or a source is unavailable.
2. **Establish the project boundary and release workflow.** Introduce persistent organizations, memberships, projects, environments and release receipts in the Cloud control plane. Prove that two synthetic organizations cannot read or operate on each other's resources. Resolve app-only provider permission, then prove approved merge to live digest, a rejected release, replay handling and recovery. Keep customer builds in their own CI until PAIGE Cloud has a secure build execution boundary.
3. **Deliver private PR previews and measurable operations.** Test protected per-PR URLs with an expiration policy. Add per-environment release timings, outside-host availability probes, actionable incident alerts and a timed backup restore. Measure usage and enforce project limits on the shared host before adding workloads.
4. **Run an invited pilot.** Use a second independent application project to prove onboarding, access removal, isolation, recovery and cost attribution. Use the pilot evidence to choose capacity, support commitments and a billing model.
5. **Add API and MCP connections after the platform controls work.** Apply the same project authorization, audit receipts and rate limits to connected agents. Keep signup and onboarding for the PAIGE Agent AI application with EXP00 and EXP01.
